# Native MCP execution

Use the established live-tool path for simple presets/root/camera keys, editing an existing scene, catalog geometry/animals and existing uploaded assets. This preserves the full connected feature set without source baking or installing Python/Node dependencies. Source-level body retiming/composition and measured wall-contact choreography use the compiled route instead. Do not rebuild its dense arrays manually.

1. Discover the connected ToonKit tool suffixes and browser API. Read the 3D catalog once, narrowing to the needed kinds. Use its actual enums, fields and limits; follow cursors if paged. Read [MCP contract](mcp-contract.md) for nested grammar. No AI generation guide or credit quote for deterministic work.
2. State a compact shot plan: duration/FPS/aspect, actors or assets, camera framing and movement, key moments and required support/obstacles. For an edit, change only requested objects/channels and preserve unrelated keys. Source and model media must already exist; do not generate a replacement without authorization.
3. Show the canvas, create a node only when needed, and open that exact editor/timeline. Read the logical scene and keep its actual IDs/revision. Missing scene and an intentional empty scene are different. Never reinitialize an existing scene to avoid inspecting it.
4. Calculate positions, camera and endpoint frames before mutation. Frame range is 0..duration*fps-1. Native presets play their normal cadence; slowing only root travel does not produce body slow motion. For calibrated boxes use bottom-center pivot: position.y=desiredCenter.y-height/2 when unrotated. The compiler's standard-library geometry/camera helpers may be imported for harder arithmetic, without FBX setup. Do not assume another primitive's pivot or bounds equal a box's.
5. Send compact same-domain MCP batches within live count/byte limits. Keep object.add and dependent clientRef commands in the same batch; later batches use returned IDs. Timing precedes keys, all root/camera keys precede pose overlays. Apply a native preset once to its catalog slot; repeated preset calls do not sequence clips. Joint corrections are local/additive, not invented anatomical angles.
6. Record the exact request/key and receipt before moving on. PENDING means wait for that mutation to apply; preserve the key after transport uncertainty. Before the next write read the current logical revision. On a conflict, inspect what exists, preserve concurrent edits and submit only missing authorized changes with a fresh revision/key; never blindly repeat an add. Compatibility flags may describe normalization or redaction: inspect the concrete flag and affected operation instead of disabling unrelated supported features.
7. Read back the affected fields/keys and required scene totals after application. For simple linear motion, check endpoints and interactions; for curved/interpolated paths calculate relevant intermediate frames. Confirm subject framing, support and the full requested tail. Only claim the checks actually performed. A camera hold, offscreen actor or intentional occlusion can be valid direction. Advanced physical/body checks require measured source evidence.
8. Before Export, check a fresh revision and the exact visible editor: expected objects and timing, assets loaded, clean Save state, one enabled Export. Reopen a stale editor rather than saving old initial values over new data. Record baseline output IDs and an export attempt before the normal browser click. If readiness fails before any click, correct readiness and retry. If the click result is lost, inspect progress/output; do not blindly click again.
9. Wait in bounded windows without MCP polling during frame capture. After completion, find the unique new video connected from this source node, then match its exact DOM node and decoded duration/dimensions/error. The small preview inside a 3D node is not an export. If offscreen, reveal that specific output once. Group this run's delivered nodes using MCP and return the visible canvas link.

Use the host's normal browser tools; Codex and Claude browser APIs differ. Browser DOM video metadata and recovery limits are documented in [execution](execution.md#export-and-delivery) and [Claude handoff](direct.md#visible-browser-export-on-claude-code). Apply only the route-relevant parts; native work does not need a compiled bundle or a compiler export ticket. Keep a small durable request/receipt record for uncertain writes/clicks; do not create a second scene implementation or large adapter for a few native operations.
